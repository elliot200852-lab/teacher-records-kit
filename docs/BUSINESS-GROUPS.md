# 業務組庫（人讀版）

「業務記錄」這一頁的設計是：**一組業務一張卡，每組欄位不一樣**。
這份文件把內建的十一組逐一講清楚——它記什麼、有哪些欄位、常用什麼分類詞、適合誰用。

- **機器正本**是 `config/business-groups.library.json`（安裝時 AI 從那裡念清單給你勾）。
  兩邊有出入以 JSON 為準。
- 你勾了哪幾組、每組實際長什麼樣，記在 `config/tabs.json` 的 `business.groups`。
- 改完設定要跑一次 `python3 scripts/build_config.py` 才會生效。

> `[[待確認：業務組清單由 David 校對]]`
> 這份清單依台灣中小學處室分工整理，出自一般校務常識，尚未經現場逐條校對。
> 用起來覺得哪一組不對、少了什麼，直接跟 AI 說，改設定就好——**不用改程式，也不用搬資料**。

---

## 先講三件事

**一、欄位是建議，不是規格。**
每一組的欄位只決定「新增的時候表單長什麼樣」。你之後在記錄檔裡自己多寫一行
「承辦人分機：2317」，系統照樣把它收進那一則的欄位裡。
所以**改欄位名不需要搬資料、加欄位不需要重裝**。

**二、不用一次勾滿。**
先勾兩三組你確定在跑的線，用一個月，缺什麼再加。勾太多只會讓分頁變得很吵。

**三、任何一組都能接回學生與課程。**
每一則都有「關聯」欄，語法 `<種類>/<對象>/<記錄id>`，
例如 `students/S-03/2026-09-10`。這是三個分頁真正串起來的地方。

## 十一組

### 1. 導師班務 `homeroom`

**用途**　帶班每天在處理的事：親師溝通、聯絡簿、出缺席、獎懲、班費、午餐。

**欄位**

| 欄位 | 型別 |
|---|---|
| 學生/對象 | 文字 |
| 事件 | 文字 |
| 處理 | 文字 |
| 後續 | 文字 |

**分類詞**　`#親師溝通` `#聯絡簿` `#家庭訪問` `#班親會` `#班級經營` `#出缺席` `#獎懲` `#班費` `#營養午餐`

**適合誰**　所有導師。這是導師最常用的一組——「今天跟誰的家長講了什麼、怎麼處理、後續要追什麼」，
一則一分鐘寫完，期末回頭看就是一整年的親師互動史。

### 2. 輔導／個案追蹤 `guidance`

**用途**　個案的晤談與追蹤。個案一律用代號；要連回學生記錄時在「關聯」欄填 `students/<代號>/<紀錄id>`。

**欄位**

| 欄位 | 型別 |
|---|---|
| 個案代號 | 文字 |
| 來源 | 選項：導師轉介／自行求助／家長／其他 |
| 主訴/議題 | 文字 |
| 晤談摘要 | 文字 |
| 評估 | 文字 |
| 處遇/介入 | 文字 |
| 追蹤與下次 | 日期 |

**分類詞**　`#初談` `#個別晤談` `#團體` `#家長晤談` `#轉介` `#通報` `#結案` `#追蹤`

**適合誰**　輔導老師、兼任輔導的導師、做認輔的老師。

**搭配用法**　個案本人的觀察放**學生記錄**分頁（一個個案一張卡），
這一組放結構化的晤談欄位，兩邊用「關聯」接起來。
沒有帶班的輔導老師可以把代號前綴設成 `C`，代號長成 `C-01`，
`data/roster.csv` 就是你自己的個案對照表。

## 兩層開放選項怎麼運作

這套系統不假裝十一組就涵蓋了全台灣老師的工作。所以有兩層可以往外開。

### 第一層：每一組都能加自己的欄位與分類詞

你勾了某一組之後，AI 一定會問你這句：

> 「這一組本來會問你這幾個欄位：〔念出來〕。**還有沒有你自己要記的欄位？**」

你加的欄位要講三件事：名稱、型別（文字／日期／從幾個選項挑一個）、
（選項類的）可以挑哪些值。分類詞同理，直接說「我還要加 `#轉學`」。

實際的例子（在 `templates/answers.example.json` 裡看得到）：
「導師班務」加一個「聯絡方式」欄位，型別是選項，可選值是電話／面談／聯絡簿／訊息。

**這一層改的是表單長相**。既有記錄不受影響，不用搬資料。

### 第二層：清單外的業務，整組自己長出來

十一組都不對的時候，選「我的業務不在清單裡」。AI 會問你**四件事**：

1. **這項業務你都叫它什麼？** → 組名
2. **每次記的時候，有哪些固定要填的欄位？** → 一個一個講名稱與型別
3. **你會用哪些分類詞去標它？** → 可以留白
4. **這件事會不會跟某位學生或某門課有關，需要接得起來？** → 要不要「關聯」欄

回答完會生出一組專屬面版，寫進 `config/tabs.json`，標記成 `custom: true`。
範例看 `templates/answers.example.json` 的 `business.custom_groups`（範例是「社團經營」：
社團名稱、出席人數、下次器材／`#社課` `#成果發表` `#器材`）。

**已經在用了才想加？** 直接跟 AI 說「我還要加一組關於○○的」，
它會問完四件事再幫你加。已經記的東西一則都不會受影響。

### 從網頁上加的那條路

網頁的業務分頁有「＋ 新增業務組」，可以直接在網頁上從庫裡勾一組、或自訂一組。
**但那只會建立雲端那一張卡。** 本機的記錄檔與安全規則是以 `config/tabs.json` 為準，
所以在網頁上加完之後，記得回頭跟 AI 說一聲「我在網頁上加了一組○○，幫我同步進設定」。
網頁上也會提示你這件事。

## 想直接改設定檔的話

`config/tabs.json` 的 `business.groups` 是一個陣列，每一組長這樣：

```json
{
  "id": "club",
  "label": "社團經營",
  "fields": [
    {"name": "社團名稱", "type": "text"},
    {"name": "出席人數", "type": "text"},
    {"name": "下次器材", "type": "text"}
  ],
  "tags": ["#社課", "#成果發表", "#器材"],
  "custom": true
}
```

`type` 只有三種：`text`、`date`、`select`（`select` 要多一個 `options` 陣列）。
`id` 只能用英數與 `-` `_`，它會變成資料夾名（`data/business/<id>/records.md`）與雲端文件 id。

改完一定要跑：

```bash
python3 scripts/build_config.py
```

**改 `id` 等於換一組新的**（舊資料夾裡的記錄不會跟著搬）。要改名字改 `label` 就好，`id` 不要動。
