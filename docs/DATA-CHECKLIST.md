# 安裝前要準備什麼資料

安裝的時候，你的 AI 代理會一題一題問你。這份是**同樣那些問題的清單**，
你想先看一遍、先把資料找齊再開始，就看這份。

**沒準備好也可以開始。** 每一項底下都寫了「這一項沒有的話怎麼辦」。
系統設計成隨時可以再加東西，先裝起來用比湊齊資料重要。

範例檔全部在 `templates/`：

| 範例檔 | 是什麼 |
|---|---|
| `templates/roster.example.csv` | 學生名單長什麼樣（三欄：代號,姓名,類型） |
| `templates/contacts.example.csv` | 家長信箱名單長什麼樣（選用） |
| `templates/observation.example.md` | 學生記錄檔長什麼樣（全班型的記錄類型） |
| `templates/case-records.example.md` | 個案型記錄類型（個案追蹤／IEP／早療目標追蹤／會談紀錄 SOAP）的檔長什麼樣 |
| `templates/course-records.example.md` | 課程記錄檔長什麼樣 |
| `templates/business-records.example.md` | 業務記錄檔長什麼樣 |
| `templates/card.example.json` | 學生卡長什麼樣（IEP 的 `goals`、SOAP 的 `conceptualization`） |
| `templates/report-format.custom.example.json` | 校方自己的期末格式貼哪裡 |
| `templates/answers.example.json` | 免互動安裝的答案檔（AI 用的） |

可勾選的清單（機器正本，安裝時 AI 從這幾份念給你聽）：
`config/verticals.json`（三個方案：質性評量／IEP 追蹤／SOAP 個案）、
`config/student-streams.library.json`（學生記錄類型）、
`config/business-groups.library.json`（業務組）、
`config/report-formats.library.json`（期末產出格式）。
**每一份都是零預設**——列出來讓你勾，一個都不預先幫你勾；方案只是「唸建議」，不會替你打勾。

---

## 通用：三個分頁都會問的

| 資料 | 必填？ | 格式 | 範例 | 去哪裡拿 |
|---|---|---|---|---|
| 你的 Google 信箱 | **必填** | 電子郵件 | `someone@gmail.com` | 就是你平常登入 Google 的那個。學校帳號常被鎖住，判斷方法見 `AGENTS.md` 前置條件 |
| Firebase 六個設定值 | **必填** | 一段文字 | `apiKey`、`authDomain`、`projectId`、`storageBucket`、`messagingSenderId`、`appId` | https://console.firebase.google.com → 專案設定（左上齒輪）→ 一般 → 你的應用程式 → 網頁應用程式 → SDK 設定與配置 → Config |
| 備份資料夾 | 選填（強烈建議） | 電腦上的路徑，或 Drive 資料夾 ID | `~/Library/CloudStorage/GoogleDrive-你的信箱/My Drive/教學紀錄備份` | 裝「Google 雲端硬碟」桌面程式（https://www.google.com/drive/download/ ）→ 在雲端硬碟裡建一個資料夾 |

**沒有的話怎麼辦**：Firebase 那六個值一定要有，AI 會全程帶你去申請。
備份資料夾可以之後再設，跟 AI 說「幫我設定備份」就好。

## 分頁一：學生記錄

### 這頁記什麼

一位學生一張卡，卡裡是你對他的觀察。
**寫具體發生的事，不要寫評語**——「他今天很棒」寫進去半年後你看不懂，
「輪到他當記錄，他把三個人的說法整理成一句話」半年後你還記得那個畫面。

整班層次的觀察（今天全班的氛圍、某個共同事件）記在同一頁上方的「班級整體觀察」，
那是一個獨立的地方，不算在任何一位學生名下。

---

### 先看：你最像哪一種？（三個方案）

學生記錄不能全部混在一起，所以再分**記錄類型**：一種類型一組欄位、一組分類詞、一個本機檔。
安裝時 AI 會先問你一句「**你最像哪一種？**」，唸出那一種通常會勾的東西——
**只是建議，一項都不會幫你預先勾**，還是你自己一項一項點頭。選「都不是」照樣裝得起來。

| 方案 | 痛點 | 建議的記錄類型 | 建議的業務組 | 期末格式 |
|---|---|---|---|---|
| ① **實驗教育／私校老師：質性評量自動化** | 整年不打分數，期末卻要從一整疊零碎筆記回頭寫出每個孩子的評語。 | `qualitative`、`subject` | `homeroom`、`parent_comm`、`meetings` | `waldorf-homeroom` |
| ② **特教／早療：IEP 目標追蹤** | 目標達成的細節每天都在發生，期末的評鑑格式卻要求逐條交代方式、標準、日期與證據。 | `iep`、`homeroom` | `special_ed`、`meetings`、`parent_comm` | `iep-tracking` |
| ③ **諮商／教練／社工：SOAP 個案紀錄** | 每次會談結束都要補寫 SOAP 或個案紀錄，手寫耗時又漏細節。 | `soap`、`case` | `guidance`、`meetings` | `case-summary` |

（機器正本＝`config/verticals.json`。下面每一種類型的欄位、提示與選項
**逐字取自 `config/student-streams.library.json`**，期末格式的段落與規則
**逐字取自 `config/report-formats.library.json`**；兩邊有出入以那兩份 JSON 為準。）

### 方案① 質性評量自動化（實驗教育／私校老師）

#### 記錄類型：質性評量觀察（不打分數）（`qualitative`）

期末要寫文字評語的老師用：每一則記一個具體事件，當下就標好它屬於哪個面向、期末要放進報告的哪一段。期末用 report_pack.py 一鍵把整年的碎片分組成素材包。

- **範圍**：**全班每一位**（名冊上的學生自動都在裡面）
- **本機檔**：`data/students/<代號>/qualitative.md`

**每一則要填的欄位**

| 欄位 | 型別 | 記錄當下的引導 |
|---|---|---|
| 面向 | 多選 | 這一則主要看見哪一塊？可複選（頭＝思考、心＝情感、手＝意志、社群＝人際）。<br>**選項**：頭·思考／心·情感／手·意志／社群·人際 |
| 報告維度 | 單選 | 期末報告的哪一段？五個維度＝評語「客觀描述」的五段，現在標好，期末就不用回頭翻。<br>**選項**：行為與自我管理／人際互動／學習態度與能力／內在特質與個人發展／挑戰與方向 |
| 課程 | 文字 | 哪一堂課或哪一塊主課程（課程 id 或科目名）；期末會依課程再分一層。 |
| 證據來源 | 單選 | 這一則是從哪裡看到的——期末寫評語每一句都要交代得出來源。<br>**選項**：工作本／課堂觀察／口說／身體／作品／親師 |
| 指標 | 文字 | 只有操作型能力才填，格式「第N條 可獨立完成／需輔助完成／尚無法完成」。情意的觀察永遠不打等級。 |

**分類詞**：`#課堂` `#主課程` `#工作本` `#口說` `#身體` `#作品` `#人際` `#突破` `#卡點`

#### 學生卡要準備的資料

不用。這一種不需要學生卡上多帶東西——名冊有代號與姓名就能開始記。

#### 期末產出：`導師質性評量（發展樣貌／客觀描述五維度／整體感受／導師建議）`（`waldorf-homeroom`）

```bash
python3 scripts/report_pack.py --format waldorf-homeroom --target S-01
python3 scripts/report_pack.py --format waldorf-homeroom --all     # 全班一包
```

**報告骨架**

| 段落 | 字數 |
|---|---|
| 發展樣貌 | 150–300 字 |
| 客觀描述｜行為與自我管理 | 60–150 字 |
| 客觀描述｜人際互動 | 60–150 字 |
| 客觀描述｜學習態度與能力 | 60–150 字 |
| 客觀描述｜內在特質與個人發展 | 60–150 字 |
| 客觀描述｜挑戰與方向 | 60–150 字 |
| 整體感受 | 依老師自己的話 |
| 導師建議 | 約 100 字 |

**書寫規則**（會原樣寫進 `-prompt.md`，你的 AI 照這幾條寫）

- 稱名不稱全名（名字只有一個字時才連姓稱呼）。
- 人稱一律用「他」。
- 先寫具體事實（哪一天、哪一節、他做了什麼、說了什麼），再自然長出教育判斷。
- 每一則只給一個主要的下一步，不要開願望清單。
- 禁止 AI 對比句：「不是A而是B」「不只是…更是」「真正的關鍵是」這一類句式一律不用。
- 禁止定型語言：懶惰、能力差、不用心、問題學生。
- 寫困難時要交代四件事：情境、他已經有的努力、教師的支持、可實踐的下一步。
- 情意的觀察不打等級——三階量表（可獨立完成／需輔助完成／尚無法完成）只用在操作型指標。
- 素材包裡沒有的事不要寫。全班共同上過的材料只能證明「班上上過」，不能寫成每個孩子都學會了。
- 「整體感受」那一段由老師自己寫，AI 不代筆。

科任老師的評語走另一個格式 `subject-4`（`科任評語四項（關係／參與／可見的學習證據／下一步）`，全篇 320–450 字）：

| 段落 | 字數 |
|---|---|
| 關係 | 一段 |
| 參與 | 一段 |
| 可見的學習證據 | 一段 |
| 下一步 | 一句到兩句 |

### 方案② IEP／早療目標追蹤（特教）

#### 記錄類型：IEP／早療目標追蹤（`iep`）

特教與早療：先把學年／學期目標建在學生卡片上（card.json 的 goals），之後每一則都掛在某一條目標下，期末用 report_pack.py 一鍵出「每目標一表」的追蹤報告。

- **範圍**：**只有你列入的學生**（`data/roster.csv` 第三欄，或網頁上「＋ 列入學生」）
- **本機檔**：`data/students/<代號>/iep.md`

**每一則要填的欄位**

| 欄位 | 型別 | 記錄當下的引導 |
|---|---|---|
| 目標編號 | 目標（從學生卡的目標清單選） | 這一則對應哪一條目標（從這位學生 card.json 的 goals 選，例如 G1）。填了不存在的編號會被擋下來。 |
| 達成情形 | 單選 | 對照那一條目標的評量標準，這一次到哪裡了。<br>**選項**：未開始／初步／部分達成／達成／類化 |
| 證據 | 單選 | 這個判斷是根據什麼——評鑑要看得到來源。<br>**選項**：觀察／作品／測驗／家長回報 |
| 支持策略 | 文字 | 這一次用了什麼調整或支持（提示層級、教材調整、環境安排…）。 |
| 下一步 | 文字 | 下一次要往哪裡推一格；一則只寫一個。 |
| 會議決議 | 文字 | 只有個案會議那一則才填：會議上決定了什麼。 |

**分類詞**：`#IEP` `#鑑定` `#資源班` `#巡迴` `#個案會議` `#轉銜` `#早療` `#家長回報`

#### 學生卡要準備的資料：**IEP 目標清單（七欄）**

這一種的每一則都掛在某一條目標底下，所以**先把該生的 IEP 目標給 AI**，
它會寫進 `data/students/<代號>/card.json` 的 `goals`（範本＝`templates/card.example.json`）。
一條目標要講這七件事：

| 欄位 | 說明 |
|---|---|
| `id` | 目標編號（`G1`、`G2`…）。AI 幫你編，記錄時的「目標編號」欄填的就是它 |
| `領域` | **特教**＝認知／溝通／行動／情緒行為／社會／生活自理／學業；**早療**＝認知／語言／動作／社會情緒／生活自理。依鑑定結果填，不自行改名 |
| `學年目標` | 這一學年要到哪裡 |
| `學期目標` | 這一學期的那一格（可檢核） |
| `評量方式` | 怎麼量（課堂觀察紀錄、檢核表＋家長回報…） |
| `評量標準` | 到什麼程度算通過（「連續三次上課中有兩次做到即通過」） |
| `期程` | 例如 `2026-09 至 2027-01` |

**手邊沒有 IEP 也可以先裝**：卡片先空著，之後把 IEP 給 AI 再補。
只是在補進去之前，記錄表單上的「目標編號」欄沒有東西可選（網頁會直接寫「先在上方『目標清單』加目標」），
而且**填了卡片上沒有的編號會被 `append_record.py` 當場擋下來**並列出可用的目標。

#### 期末產出：`IEP／早療目標追蹤報告（每目標一表＋期末總評）`（`iep-tracking`）

```bash
python3 scripts/report_pack.py --format iep-tracking --target S-02
```

**報告骨架**

| 段落 | 字數 |
|---|---|
| 一、現況能力與教育需求 | 200–400 字 |
| 二、學年與學期教育目標達成情形 | 每目標一段 |
| 三、評量方式、日期與標準 | 一表 |
| 四、相關服務與支持策略 | 100–300 字 |
| 五、行為功能介入（如有） | 選填 |
| 六、轉銜與下一階段建議 | 100–200 字 |
| 附：個案會議紀錄（三段式） | 選填 |

**書寫規則**

- 每一條達成情形都要指得出證據（哪一天、什麼證據來源），沒有紀錄就寫「本期未蒐集到紀錄」，不推估。
- 達成情形只用五級：未開始／初步／部分達成／達成／類化。
- 先寫具體事實再寫專業判斷；描述行為，不描述人格。
- 稱名不稱全名；人稱一律用「他」。
- 禁止定型語言（懶惰、能力差、不用心、問題學生）。
- 禁止 AI 對比句（「不是A而是B」「不只是…更是」「真正的關鍵是」）。
- 每一條目標只寫一個主要的下一步。
- 困難要交代情境、已有努力、提供過的支持與可實踐的下一步。
- 早療五領域＝認知／語言／動作／社會情緒／生活自理；特教領域依鑑定結果填，不自行改名。
- 家長回報的內容要標明是家長回報，不寫成教師的直接觀察。

### 方案③ SOAP 個案紀錄（諮商／教練／社工）

#### 記錄類型：會談紀錄（SOAP）（`soap`）

諮商、教練、社工：一次會談一則，四段拆開記（個案的話進 S、看得到的行為進 O、你的評估進 A、下一步進 P）。期末或結案用 report_pack.py 出個案摘要。

- **範圍**：**只有你列入的學生**（`data/roster.csv` 第三欄，或網頁上「＋ 列入學生」）
- **本機檔**：`data/students/<代號>/soap.md`
- **舊設定相容**：v3 alpha 把 `counseling` 併進 `soap`，舊設定寫 `counseling` 也認得（`aliases`），檔名仍照舊 id 走，資料不必搬。

**每一則要填的欄位**

| 欄位 | 型別 | 記錄當下的引導 |
|---|---|---|
| 會談次數 | 文字 | 第幾次會談（只填數字）；個案摘要依這個排序，沒填就用日期排。 |
| 會談形式 | 單選 | 這一次是什麼形式的接觸。<br>**選項**：個別／團體／家長／教師諮詢／電話／線上 |
| S 主觀 | 文字 | 個案自己說的話與主觀感受，盡量留他的原話，不要先翻譯成專業術語。 |
| O 客觀 | 文字 | 你可以觀察到的行為與事實：出席、表情、語速、完成度、互動。不放推論。 |
| A 評估 | 文字 | 你的專業評估與假設。寫成假設（「可能與…有關」），不寫成定論。 |
| P 計畫 | 文字 | 下一步處遇：這次結束到下次之間，你要做什麼、他要做什麼。 |
| 風險評估 | 單選 | 這一次的風險判斷；期末摘要會把它拉成一條趨勢線。<br>**選項**：無／低／中／高 |
| 下次時間 | 日期（YYYY-MM-DD） | 下次會談日期 YYYY-MM-DD。 |

**分類詞**：`#初談` `#個別` `#團體` `#家長` `#教師諮詢` `#危機` `#轉介` `#結案`

#### 學生卡要準備的資料：**個案概念化（五格）**

期末的個案摘要與結案報告從這五格開始，寫進 `data/students/<代號>/card.json` 的 `conceptualization`：

| 格 | 要寫什麼 |
|---|---|
| `主訴` | 個案自己說的、這次來談的是什麼事 |
| `背景` | 相關的家庭、學校、發展或就醫脈絡，只寫與處遇有關的 |
| `評估假設` | 你的專業假設，**寫成假設不寫成定論** |
| `處遇目標` | 這一段要往哪裡走，可檢核 |
| `結案標準` | 達到什麼就可以結案——**結案報告會逐條對照這一格** |

現在講得出來的先給，之後隨時能改。

#### 期末產出：`個案摘要／結案報告（個案概念化＋歷程＋進展＋建議）`（`case-summary`）

```bash
python3 scripts/report_pack.py --format case-summary --target S-03
```

**報告骨架**

| 段落 | 字數 |
|---|---|
| 一、個案概念化 | 200–400 字 |
| 二、歷程摘要 | 每次一段或一表 |
| 三、進展評估 | 150–300 字 |
| 四、風險與安全 | 100–200 字 |
| 五、處遇建議或結案評估 | 150–300 字 |

**書寫規則**

- S 只放個案自己說的話與主觀感受，O 只放可觀察的行為與事實，A 是專業評估與假設，P 是下一步處遇——四段不互相混。
- 評估寫成假設（「可能與…有關」），不寫成診斷結論。
- 個案一律以代號稱呼；正文不出現真名（真名只留在本機名冊）。
- 風險判斷只用四級：無／低／中／高，並寫出根據。
- 提到當事人時人稱一律用「他」；提到其他人只寫角色（導師、家長），不寫姓名。
- 禁止 AI 對比句（「不是A而是B」「不只是…更是」「真正的關鍵是」）。
- 禁止定型語言（懶惰、能力差、不用心、問題學生）與人格標籤。
- 每一次會談只寫一個主要的下一步。
- 缺漏的次數照實標「未留下紀錄」，不補寫。

### 素材包不是評語：分工先講清楚

`report_pack.py` **不呼叫任何 AI、不寫任何一句評語**。它只做四件確定性的事：
依格式分組、附統計、標出缺漏、附上骨架與規則。輸出兩個檔到 `exports/`：

- `<代號>-<格式>-素材包.md` — 分好組的事實，**一個字都不是它編的**
- `<代號>-<格式>-prompt.md` — 報告骨架＋書寫規則＋**定稿前的稽核清單**＋一段給 AI 的固定指令

**本文由你的 AI 照那份指令寫、由你定稿。**
`waldorf-homeroom` 的「整體感受」那一段更明確：**由老師自己寫，AI 不代筆**。

不開終端機也可以：網頁上學生明細頁有「**產生期末素材 ▾**」、一覽頁有「**產生全班期末素材 ▾**」，
下載的 .md 跟腳本出的一樣。

**學校有自己的表格** → 用 `--format custom`：
`cp templates/report-format.custom.example.json config/report-format.custom.json`，
把校方的報告標題、每段要寫什麼、字數限制貼進去。`groupBy` 填你記錄時實際用的欄位名
（例如「報告維度」「觀察向度」「科目」），`rules` 留空就用格式庫 `custom` 的通用規則：

- 稱名不稱全名；人稱一律用「他」。
- 先寫具體事實再長出教育判斷。
- 每則只給一個主要的下一步。
- 禁止 AI 對比句（「不是A而是B」「不只是…更是」「真正的關鍵是」）。
- 禁止定型語言（懶惰、能力差、不用心、問題學生）。
- 寫困難要交代情境、已有努力、教師支持與可實踐的下一步。
- 情意觀察不打等級。
- 素材包裡沒有的事不要寫。

`exports/` 裡的檔**含名冊真名**（那是給你自己看的），別放到公開的地方；那個目錄已經在 `.gitignore` 裡。

### 三個方案都不是？通用類型在這裡

三個方案是「痛點最集中」的三種老師，不是全部。下面三種通用類型沒有綁方案，隨時可以勾：

#### 導師班級學生紀錄（`homeroom`）

帶班導師對班上每一位學生的日常觀察：課堂、學習態度、人際、情緒、生活。不預先分維度，想到什麼記什麼。

- **範圍**：**全班每一位**　**適用角色**：帶班導師
- **固定欄位**：（沒有固定欄位——只有日期、分類詞與正文；要加自己的欄位見下面「自訂欄位與分類詞」）
- **分類詞**：`#課堂` `#主課程` `#學習態度` `#專注意志` `#人際` `#情緒` `#突破` `#親師` `#生活`
- **本機檔**：`data/students/<代號>/observations.md`（沿用 v2 的檔名，所以舊資料原地可用）

#### 任課老師學生紀錄（`subject`）

科任／任課老師對學生的觀察。跨班上課時「科目」欄讓你分得出這則是哪一科；「觀察向度」對應期末科任評語的四項。

- **範圍**：**全班每一位**　**適用角色**：科任／任課老師（跨班上課也適用）
- **本機檔**：`data/students/<代號>/subject.md`
- **分類詞**：`#課堂` `#學習態度` `#作業` `#專注` `#人際` `#亮點` `#卡點`

| 欄位 | 型別 | 記錄當下的引導 |
|---|---|---|
| 科目 | 文字 | 這一則是哪一科的課堂（跨班上課時靠它分得出來）。 |
| 觀察向度 | 單選 | 期末科任評語的四項；一則對一項就好，不用四項都填。<br>**選項**：關係／參與／可見的學習證據／下一步 |
| 證據來源 | 單選 | 這一則是從哪裡看到的。<br>**選項**：工作本／課堂觀察／口說／身體／作品／親師 |

期末走 `--format subject-4`（見方案①最後）。

#### 個案追蹤（通用）（`case`）

被列入個案的學生：來源、議題、做了什麼、下次追蹤什麼。要寫 SOAP 的請改用「會談紀錄（SOAP）」。

- **範圍**：**只有你列入的學生**　**適用角色**：導師、輔導老師、個管老師
- **本機檔**：`data/students/<代號>/case.md`
- **分類詞**：`#初談` `#個別晤談` `#家長晤談` `#轉介` `#通報` `#結案`

| 欄位 | 型別 | 記錄當下的引導 |
|---|---|---|
| 來源 | 單選 | 這個個案是誰轉過來的。<br>**選項**：導師轉介／自行求助／家長／輔導室／其他 |
| 主訴／議題 | 文字 | 這一次處理的是什麼事（用他自己的話，不要先下結論）。 |
| 處遇／介入 | 文字 | 你這一次實際做了什麼。 |
| 追蹤與下次 | 日期（YYYY-MM-DD） | 下次要追蹤的日期 YYYY-MM-DD。 |

期末走 `--format case-summary`（`case` 也吃這個格式）。

#### 我的學生紀錄類型不在清單裡（`custom`）

選這個，AI 會問你四件事——這個類型叫什麼、每次要記哪些固定欄位、常用的分類詞、是全班每一位都有還是只有你列入的學生——然後幫你生一種專屬類型寫進 config/tabs.json。期末產出用 custom 格式（把你們學校的格式標題貼進 config/report-format.custom.json）。

跟 AI 說「我要的類型不在清單裡」，它會問你**四件事**：

1. **這個類型你都叫它什麼？**（例如「社團觀察」「認輔紀錄」）
2. **每次記的時候，有哪些固定要填的欄位？**（一個一個講名稱與型別）
3. **你會用哪些分類詞去標它？**（可以留白）
4. **這一種是全班每一位都有，還是只有你列入的學生？**（＝範圍）

回答完 AI 會幫你生一種專屬類型寫進 `config/tabs.json`。英文短名（會變成本機檔名
`data/students/<代號>/<短名>.md`）由 AI 自己取，不用你煩惱。
範例看 `templates/answers.example.json` 裡 `students.custom_streams` 那一段。

**已經在用了才想加？** 直接跟 AI 說「我還要一種記○○的」，
已經記的東西一則都不會受影響。網頁上也能臨時加一種，但那只有網頁看得到——
加完要回頭跟 AI 說一聲，讓它寫進 `config/tabs.json`，本機檔與安全規則才跟得上。

### 兩件要先弄懂的事

- **範圍是「全班每一位」的類型**（`qualitative`、`homeroom`、`subject`）：名冊上的學生自動都在裡面，不用做任何事。
- **範圍是「只有列入的學生」的類型**（`case`、`iep`、`soap`）：
  只有你列入的孩子才有這一種紀錄。列入誰寫在 `data/roster.csv` 的**第三欄**
  （分號分隔，例如 `case;iep`），網頁上也能在那一種類型下按「＋ 列入學生」或「移出」，
  兩邊會同步。**「移出」只是把名冊上那個字拿掉，紀錄一則都不會刪。**

**同一位學生在不同類型各有一份紀錄，彼此看不到彼此。** 本機也是一種類型一個檔
（`data/students/S-03/observations.md`、`data/students/S-03/soap.md`…）。

### 自訂欄位與分類詞：每一種都可以加

勾了某一種之後，AI 會問你兩句：

> 「這一種本來會問你這幾個欄位：〔念出來〕。**還有沒有你自己每次都要記的欄位？**」
> 「這一種常用的分類詞我這邊有〔念幾個〕。**你有沒有自己習慣用的說法要加？**」

你加的欄位要講三件事：名稱、型別（**文字** / **日期**（`YYYY-MM-DD`）/ **從幾個選項挑一個**）、
（選項類的）可以挑哪些值。分類詞直接說「我還要加 `#轉學`」就好。

> **欄位不是規格，是建議。** 它只決定「新增的時候表單長什麼樣」。
> 你之後在記錄檔裡多寫一行「導師回應：已聯絡家長」，系統照樣把它收進那一則的欄位裡
> ——不用改設定、不用搬資料。所以不用在安裝的時候想到十全十美。
> （唯一的例外是 IEP 的「目標編號」：那一欄會真的去比對學生卡上的目標，填錯會被擋下來。）

### 安裝前要準備

| 資料 | 必填？ | 格式 | 範例 | 去哪裡拿 |
|---|---|---|---|---|
| 你最像哪一種方案 | 選填（有「都不是」） | ①②③或都不是 | ② 特教／早療：IEP 目標追蹤 | 你自己決定；只影響 AI 唸什麼建議，不會替你勾 |
| 要不要這個分頁 | **必填** | 要／不要 | `要` | 你自己決定 |
| 班級人數 | **必填**（要這頁的話） | 數字 | `26` | 你自己知道 |
| 代號前綴 | **必填**（有預設值 `S`） | 英數 | `S` → 代號變成 `S-01`；填 `5B` → `5B-01` | 你決定 |
| 你要哪幾種記錄類型 | **必填**（要這頁的話） | 從上面那幾種勾，可複選，也可以一種都不勾 | 質性評量觀察＋任課老師學生紀錄 | 你自己在記什麼 |
| 每種要不要加自己的欄位／分類詞 | 選填 | 欄位名＋型別；`#開頭` 的分類詞 | 個案追蹤加「校內協同」（文字） | 你每次都要填的那些東西 |
| 個案型類型要列入哪些學生 | 選填（可以先空著） | 代號，逗號分隔 | `S-02, S-07` | 你自己知道；之後隨時能改 |
| **IEP 目標**（勾了 `iep` 才要） | 選填（可以先空著） | 一條目標七欄，見上面 | 見 `templates/card.example.json` | 該生的 IEP 正本 |
| **個案概念化**（勾了 `soap` 才要） | 選填（可以先空著） | 五格 | 見 `templates/card.example.json` | 你腦袋裡就有 |
| 學生姓名對照 | 選填（強烈建議） | CSV 三欄：代號,姓名,類型 | 見 `templates/roster.example.csv` | 校務系統匯出的班級名冊、座位表、聯絡簿封面 |
| 家長信箱 | 選填 | CSV 三欄：編號,家長1信箱,家長2信箱 | 見 `templates/contacts.example.csv` | 只有你要用「寄信給家長」功能才需要 |

名單檔的位置是 `data/roster.csv`，**三欄**：

```
代號,姓名,類型
01,學生甲,
02,學生乙,case
03,學生丙,case;iep
```

- **第一欄**可以直接寫座號（`01`，程式會自動接上前綴變成 `S-01`），也可以寫完整代號（`S-01`）。
- **第二欄**是真名。**這是整套系統裡唯一有真名的檔案，它不會上傳、不會進版本控制。**
- **第三欄**是「這位學生列入哪幾種個案型記錄類型」，分號分隔，沒有就留空。
  全班型的類型（`qualitative`、`homeroom`、`subject`）不用寫也不要寫。

### 輔導老師與特教老師：個案追蹤走哪一種

**這一頁不是只有導師能用。** v3 起，跟著某一個孩子走的紀錄一律放在學生記錄這一頁，
只是走不同的記錄類型：

- **正式的會談紀錄** → 勾 **`會談紀錄（SOAP）`（`soap`）**：S／O／A／P 四段、會談次數與形式、風險評估。
  這是敏感度最高的一種，一律代號。
- **不寫 SOAP 的個案追蹤** → 勾 **`個案追蹤（通用）`（`case`）**：來源、主訴／議題、處遇／介入、追蹤與下次。
- **特教與早療的目標追蹤** → 勾 **`IEP／早療目標追蹤`（`iep`）**：目標編號、達成情形、證據、支持策略、下一步。
- **兩種都要也可以**：同一位學生可以同時列入 `case` 與 `soap`，兩邊各記各的、互不干擾。

**跟業務記錄那一頁怎麼分**：跟著**某一個孩子**走的，放這一頁的記錄類型；
**校務層次**的事——個案會議、通報、特教鑑定的行政流程——放業務記錄的
「輔導／個案追蹤」「特教／IEP」組。兩邊用「關聯」接起來
（業務那一則的關聯欄填 `students/<代號>/<記錄id>`）。詳見 `docs/BUSINESS-GROUPS.md`。

**你不是導師、手上沒有一個「班」也沒關係**——代號可以用你自己的編法
（例如前綴填 `C` 代表 case，代號變成 `C-01`），名單檔就是你自己的個案對照表；
記錄類型就只勾 `會談紀錄（SOAP）` 或 `個案追蹤（通用）`，不用勾導師那一種。

### 沒有這些資料怎麼辦

名單一時找不到 → 先填三五個人裝起來，之後跟 AI 說「幫我把名單補上」，把檔案給它就好。
連人數都不確定（科任要記三個班）→ 先用一個班的人數。
不知道要勾哪幾種記錄類型 → 先勾你這學期一定會寫的那一種，用一個月，缺什麼再加。
個案型類型講不出要列入誰 → 先空著，類型照樣建得起來。
IEP 目標或個案概念化還沒整理 → 卡片先空著，之後補；只有「目標編號」那一欄要等目標補上才選得到。

**這一頁的內容可以匯出 Word／PDF**：學生明細頁按「匯出 ▾」，或在一覽頁按「匯出所有學生 ▾」
（一份文件、每位學生一節）；腳本是 `python3 scripts/export_docs.py --kind students`。

## 分頁二：課程記錄

### 這頁記什麼

一門課一張卡，卡裡是這門課每一次上完的記錄：講到哪、實際教了什麼、
孩子整體怎麼反應、下次要調整什麼。跟學生記錄是分開的兩件事。

新增的時候正文會預先帶四段骨架（用不到可以整段刪掉）：

```
### 課程進度
### 今天實際教了什麼
### 學生整體反應
### 下次要調整的
```

### 安裝前要準備

| 資料 | 必填？ | 格式 | 範例 | 去哪裡拿 |
|---|---|---|---|---|
| 要先建哪幾門課 | 選填 | 課名 | `分數`、`主課程`、`手工` | 你的課表 |
| 每門課是主課程還是科任 | 選填 | 三選一：主課程／科任／其他 | `主課程` | 你自己知道 |
| 課程的英文短名 | 選填 | 英數與 `-` | `fractions`、`main-block` | **AI 會自己幫你想**，不用煩惱 |
| 學季、週數、授課老師 | 選填 | 文字 | `秋二`、`3`、`王老師` | 留空不會顯示。這套不預設你跑哪種學制 |

### 這一頁的分類詞

`#進度` `#教學內容` `#學生反應` `#調整` `#亮點` `#卡點` `#規劃`

要改：改 `config/tabs.json` 裡 `courses` 那一段的分類詞清單，再跑
`python3 scripts/build_config.py`；或直接跟 AI 說「課程記錄的分類詞我想改成……」。
（學生記錄的分類詞不在這裡——那是**每一種記錄類型各有一組**，
在 `config/tabs.json` 的 `students.streams` 底下。）

### 提到個別學生的時候

**一律用代號**（`S-03`），並在「關聯」欄填 `students/S-03/<那則記錄的 id>`，
這樣從那位學生的卡也點得回這堂課。

### 沒有這些資料怎麼辦

想不出來先建一門「主課程」就好。網頁上隨時能加新的課，不用回頭重裝。

**這一頁的內容可以匯出 Word／PDF**：課程明細頁按「匯出 ▾」，
或跑 `python3 scripts/export_docs.py --kind courses`。

## 分頁三：業務記錄

### 這頁記什麼

教學以外、但你每天都在處理的事：班務、公文、會議、輔導個案、研習、報帳。
**一組業務一張卡，每一組要記的欄位不一樣**——公文要記字號與期限，
會議要記出席與決議，個案要記主訴與處遇。

**跟學生記錄的記錄類型是同一套勾選機制**：列清單、你勾、每一組再問要不要加自己的欄位
與分類詞、清單外走開放選項四題。**十一組一組都不預先幫你勾**，
你勾了哪幾組才有哪幾組（`config/tabs.example.json` 的 `business.groups` 是空陣列）。

### 安裝前要準備

| 資料 | 必填？ | 格式 | 範例 | 去哪裡拿 |
|---|---|---|---|---|

### 自訂欄位：每一組都可以加

勾了某一組之後，AI 會問你一句：「這一組還有沒有你自己要記的欄位？」
你可以加任意多個，每個要講三件事：

1. 欄位叫什麼（例如「聯絡方式」）
2. 是哪一種：**文字** / **日期**（`YYYY-MM-DD`）/ **從幾個選項挑一個**
3. 選項類的話，可以挑哪些值（例如：電話、面談、聯絡簿、訊息）

分類詞同理，直接說「我還要加 `#轉學`」。

> **欄位不是規格，是建議。** 你之後在記錄檔裡多寫一行「承辦人分機：2317」，
> 系統照樣把它收進那一則的欄位裡——不用改設定、不用搬資料。
> 所以不用在安裝的時候想到十全十美。

### 清單外的業務：開放選項

你要記的東西上面十一組都不對？選「我的業務不在清單裡」，AI 會問你**四件事**：

1. **這項業務你都叫它什麼？**（組名，例如「社團經營」）
2. **每次記的時候，有哪些固定要填的欄位？**（一個一個講名稱與型別）
3. **你會用哪些分類詞去標它？**（可以留白）
4. **這件事會不會跟某位學生或某門課有關，需要接得起來？**（要不要「關聯」欄）

回答完 AI 會幫你生一組專屬的面版。範例看 `templates/answers.example.json` 裡
`business.custom_groups` 那一段（範例是「社團經營」）。

### 沒有這些資料怎麼辦

一次想不齊很正常。**先勾你確定的兩三組**，之後隨時跟 AI 說
「我還要加一組關於○○的」，已經記的東西一則都不會受影響。

**這一頁的內容可以匯出 Word／PDF**：業務組明細頁按「匯出 ▾」，
或跑 `python3 scripts/export_docs.py --kind business`。

## 三個分頁怎麼接起來

每一則記錄都可以填「關聯」，語法是 `<種類>/<對象>/<記錄id>`，種類有四種：
`students`、`class`、`courses`、`business`。

實際例子：

- 這堂課某個孩子有突破 → 課程記錄那一則的關聯填 `students/S-03/2026-09-15-1435`
- 這份公文跟某位學生的轉學有關 → 業務記錄那一則的關聯填 `students/S-07/2026-09-10`
- 個案會議的決議接回那位學生的個案追蹤 → 業務（輔導組）那一則的關聯填 `students/C-02/2026-09-12`

**關聯只認到「哪一位學生的哪一則」，不分記錄類型**——同一位學生底下每一則的 id 是唯一的，
所以 `students/S-03/2026-09-12` 指得到他在任何一種記錄類型裡的那一則。

用分號分隔可以接多個。記錄 id 就是那一則的日期（同一天第二則之後會帶時間，
像 `2026-09-15-1435`）。

**不知道 id 沒關係**，跟 AI 說「把這一則接到 S-03 上個禮拜那則觀察」，它會自己去找。
